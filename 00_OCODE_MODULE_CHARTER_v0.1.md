## Purpose Kernel

**OCODE exists to let people define, understand, translate, improve, validate and deliver operational software through a simpler, inspectable structure while preserving truth, evidence, interoperability and human control.**

## Bridge Mandate

```text
Existing Source Code or Application Intent
→ Supported Source Importer
→ OCODE Operational Map
→ Compatibility / Optimization Assessment
→ Validated Target Adapter
→ Generated Artifact
→ Behavior and Safety Evidence
→ Governed Promotion
```

OCODE is intended to accept supported source inputs such as HTML/CSS, JavaScript, Python, C# and C++, normalize observed structures and intended behaviors, and later regenerate target artifacts through validated adapters.

## Hard Truth Boundary

OCODE is not presently a proven compiler replacement, universal runtime or arbitrary-code-to-any-platform translator. Source programs can depend on libraries, operating-system APIs, browser services, native permissions, memory behavior, device capabilities, credentials, proprietary frameworks and licensing constraints.

No OCODE target may be claimed as functionally equivalent until its importer, adapter and behavior validation are implemented and evidenced.

## Status Labels

- `IMPLEMENTED` — the artifact or behavior exists.
- `TESTED` — named validation has passed and is recorded.
- `PROPOSED` — designed but not built.
- `BLOCKED` — cannot be promoted because evidence, dependencies or approval is missing.
- `ASPIRATIONAL` — long-range direction only.

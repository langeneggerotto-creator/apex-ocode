# DreamMusicForge OS — Analysis Engine Canon v1.0

Status: CANONICAL SUBSYSTEM SPECIFICATION

## Purpose
DreamMusicForge Analysis Engine converts video evidence into structured technical, visual, performance, editorial, continuity, renderer-feasibility, compiler, and benchmark intelligence. It is a permanent operating subsystem of DreamMusicForge, not an optional review step.

## Constitutional relationship
This subsystem inherits DreamMusicForge principles: meaning precedes representation; music is the master clock; provider neutrality; explicit continuity; verification before canon; evidence before promotion; fail closed on unsupported claims.

## Mandatory truth model
Every claim emitted by the Analysis Engine MUST be labeled as one of:
- VERIFIED — directly observable
- MEASURED — computed from source evidence
- INFERRED — strong evidence-backed inference
- POSSIBLE — plausible but not established
- UNKNOWN — cannot be determined from available evidence

Inference must never be presented as measurement or verified fact.

## Canonical execution passes
0. Ingest + Evidence Freeze
1. Technical Analysis
2. Visual / Production Analysis
3. Performance Analysis
4. Music + Editorial Analysis
5. Continuity Seam Audit
6. Production / Renderer Feasibility
7. Compiler Synthesis
8. Final Synthesis

Each pass MUST emit both machine-readable JSON and a human-readable report.

## Pass 0 — Ingest + Evidence Freeze
Required outputs:
- immutable analysis run ID
- source asset hash
- media metadata
- frame/time coordinate system
- source provenance and capture limitations

## Pass 1 — Technical Analysis
Required analyses:
- duration, FPS, resolution, codecs, frame count
- audio format, loudness, waveform
- shot/scene candidate boundaries
- technical anomalies
- black/frozen/dropped-frame indicators where measurable

## Pass 2 — Visual / Production Analysis
Required analyses:
- performer identity
- hair and makeup
- wardrobe and accessories
- props
- environments/worlds
- production design
- lighting
- color
- cinematography

## Pass 3 — Performance Analysis
Required analyses:
- facial performance
- gaze
- breathing where observable
- gestures
- body mechanics
- choreography
- apparent singing
- emotional state
- performance evolution

Apparent singing MUST NOT be labeled verified lip sync unless phoneme-level evidence exists.

## Pass 4 — Music + Editorial Analysis
Required analyses:
- musical structure
- beat/bar/phrase relationships where measurable
- visual accents
- cut timing
- transition type
- camera/edit interaction
- motion bridges
- lyric relationships where lyrics are known
- editorial cadence and energy

## Pass 5 — Continuity Seam Audit
Mandatory whenever separately generated clips, shots, or passes are combined.

Continuity MUST be evaluated at four levels:
1. Pixel continuity — neighboring frames visually agree where a seamless continuation is claimed.
2. State continuity — identity, costume, world, pose, prop, camera, lighting, and music states obey declared invariants.
3. Causal continuity — the destination state could physically and narratively follow the source state.
4. Semantic continuity — intentional editorial discontinuities still feel like the same film.

Music continuity MUST be evaluated separately as:
- Audio continuity
- Musical continuity
- Vocal continuity
- Performance continuity

## Pass 6 — Production / Renderer Feasibility
For every shot or production event, classify whether it should use:
- DIRECT_RENDER
- CONTROLLED_CONTINUATION
- LAYERED_COMPOSITING
- EDITORIAL_ILLUSION
- EXTERNAL_SPECIALIST_STAGE
- REDESIGN_REQUIRED

Evaluation must use the Renderer Capability Atlas and distinguish documented, measured, assumed, unsupported, and unknown capabilities.

## Pass 7 — Compiler Synthesis
Required outputs:
- Film Genome
- Production Graph
- Shot Contracts
- Transition Contracts
- Renderer Tasks
- Assembly Tasks
- Verification Contracts
- reusable production principles/laws

## Final Synthesis
Required outputs:
- complete benchmark report
- machine-readable truth package
- quality scores with provenance
- failures
- renderer limitations
- repair strategy
- DreamMusicForge engineering backlog

## Canonical continuity doctrine
Pixel continuity is mandatory only when physical continuation is claimed.
State continuity is mandatory wherever invariants are declared.
Causal continuity is mandatory whenever state B claims to physically follow state A.
Semantic continuity is mandatory across intentional edits, scene changes, costume changes, and world changes.

## Canonical production insight
DreamMusicForge must not optimize exclusively for invisible clip joins. Professional music-video quality can maintain one performer identity, one master song, one emotional architecture, one motif system, and one directing language across intentionally different shots and worlds.

## Evidence rule
No analysis becomes canonical without a source hash, run ID, truth labels, and retained evidence sufficient to reproduce or audit the result.
